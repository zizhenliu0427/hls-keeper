> **切片 1「操作矩阵」已实施（2026-08-05）。** 实施结果与方案的差异记录在文末 §10。

## 1. 现状盘点（问题的量化）

任务页现有 **44 个带 id 的元素**，render() 里有 **36 条互相独立的 `.hidden =` 布尔判断**。
每加一个功能就多一个按钮加一条判断，这就是「五个按钮并排、没有主次」的直接原因。

当前任务视图的全部控件（按现状顺序）：

| 区块 | 控件 | 问题 |
|---|---|---|
| 头部 | title / subtitle / status 胶囊 | 基本可用 |
| 进度 | progress 条 + coverage 覆盖条 + 4 个数字卡 + notice | 两条进度条并排含义不同但没标注主次；notice 同时承担指引/进度/错误三种语气 |
| 面板 | sourcePanel（网页连接）/ locationPanel（成品位置）/ activityPanel（流水）/ missingPanel（缺口） | 四个面板永远全部展开，一屏放不下；缺口面板内部又有 5 个控件 |
| 操作区 | choose / resume / pause / backToVideo / switchAssisted / fillDirect / smartFill / captureSpeed(+seekBoost×2) / verifySegments / merge / mergeExternal / openOutput / subtitles / deleteSegments / deleteOutput / removeTask | **16 个操作平铺**，只靠 hidden 组合裁剪；主操作不突出，危险操作和常规操作混排 |
| 底部 | diagnosticsPanel | 可用 |

用户实测反馈（历史累计）：
- 「导入了也不知道哪里能继续捕获」——主操作不明确；
- 「点继续没反应」——按钮可点但无事可做（已用文案补救，根因是按钮不该出现）；
- 「保存位置为什么是 Downloads」——分片来源和成品去向混在一栏（已拆，方案沿用）；
- 「补全位置只能看到头几个」——列表实时重排（已修为稳定顺序+分页，方案沿用）。

## 2. 目标

打开任务页 3 秒内能回答：
1. 这个任务现在处于什么阶段？
2. **我现在最该点哪一个按钮？**（有且只有一个高亮主操作）
3. 进度到哪了、还缺什么？
4. 出错了的话，怎么办？

不追求：视觉炫技、组件库、框架迁移。保持零依赖纯 HTML/CSS/JS。

## 3. 核心方案：状态驱动的操作区

### 3.1 用一张矩阵取代 36 条散落判断

新增单一函数 `actionsFor(state, context)` 返回 `{ primary, secondary[], overflow[] }`，
render() 只负责摆放，不再逐个算 hidden。矩阵如下（这张表是本方案最重要的产出）：

| 状态（+条件） | 主操作（高亮，≤1 个） | 次操作（普通，≤2 个） | 收进「更多」菜单 |
|---|---|---|---|
| ready（未开始） | 开始下载 / 选择位置并开始 | — | 从列表移除 |
| downloading（直接下载中） | 暂停 | — | 更多 |
| capturing/waiting · **未接上网页** | 打开原网页 | 暂停 | 更多 |
| capturing/waiting · 已接上 · 有缺口 · **有真实 URL** | 直接补齐缺口 | 智能补全 · 暂停 | 播放加速面板保留在缺口区内 |
| capturing/waiting · 已接上 · 有缺口 · 无真实 URL | 智能补全 | 返回网页 · 暂停 | 更多 |
| 已齐（missing=0, done>0） | **检查并生成视频** | 检查分片有效性 | 保存字幕 · 更多 |
| merging / exporting | —（只显示进度，操作区隐藏） | — | — |
| complete | 打开生成的视频 / 在文件夹中显示 | — | 清理临时 · 删除成品 · 从列表移除 |
| error · OUTPUT_QUOTA | 选择位置并重新生成 | — | 更多 |
| error · 其他 | 继续（重试） | 改用网页辅助（仅符合条件时） | 更多 |
| paused | 继续 | — | 更多 |

规则：
- **主操作永远 ≤1 个**，用填充色按钮；次操作 ≤2 个，描边按钮；其余全部进「更多 ⋯」下拉。
- 危险操作（清理临时 / 删除成品 / 从列表移除）**只**存在于「更多」菜单，红字，点击仍需 confirm。
- 无事可做的按钮**不出现**，而不是出现后弹「无事可做」的提示。
- 「暂停」在任何运行态都放在次操作末位，位置固定，肌肉记忆可用。

### 3.2 提示条（notice）按语气分四型

现在一条 notice 混用所有语气。改为固定四型，颜色和图标绑定语气：

| 型 | 用途 | 样式 |
|---|---|---|
| 指引 | 「下一步该做什么」 | 中性底，📍 |
| 进行 | 阶段进度（生成中/提交中/校验中） | 蓝底，旋转小圈 |
| 成功 | 完成 | 绿底，✓，完成时不再依赖 alert（保留一次弹窗作强提醒可配置） |
| 需处理 | 错误/卡住 | 红底，与主操作按钮直接对应（如 OUTPUT_QUOTA → 主操作就是修复动作） |

## 4. 页面结构重排（任务视图）

```
┌ Hero ───────────────────────────────────────┐
│ 标题 · 清晰度 · 来源徽章        [状态胶囊]  │
│ [主操作]  [次操作] [次操作]        [⋯ 更多] │  ← 操作区上移到首屏
├ 进度 ───────────────────────────────────────┤
│ 覆盖条（主，hover 提示时间/缺口）           │
│ 数字行：已完成 / 待补 / 已保存 / 速度（一行小字，不再四张大卡）│
│ 提示条（四型之一）                          │
├ 折叠区（手风琴，同时最多展开一个）──────────┤
│ ▸ 需要补全的位置（有缺口时默认展开）        │
│ ▸ 实时分片流水（抓取中默认展开）            │
│ ▸ 连接与保存位置（合并了 source+location）  │
│ ▸ 诊断信息                                  │
└─────────────────────────────────────────────┘
```

变化点：
- **操作区从页面底部移到 Hero 里**——现状要滚过四个面板才看到按钮，这是「不知道点哪」的另一半原因；
- 传统 progress 条与覆盖条合并为一条：覆盖条本身就是进度（蓝色占比），合并时切换为百分比模式；
- 四张数字大卡压成一行小字，为折叠区腾出首屏空间；
- 四个面板改手风琴，**按状态决定默认展开哪一个**（有缺口→缺口区；抓取中→流水；其余→全收起）；
- 播放加速 + 快进参数移入「需要补全的位置」面板内部（它们只在补缺口时有意义）。

## 5. 下载中心列表页

- 卡片右上角加状态徽章（颜色同任务页胶囊）；
- 每张卡片同样只给一个主操作（等待选择→两个下载按钮；进行中→查看下载；已齐→生成视频；完成→打开文件）；
- 「导入旧捕获目录」「清除全部未开始的发现」移入页头的次级工具条，不与任务卡片抢视觉；
- 列表持久排序：进行中 > 需处理 > 等待选择 > 已完成。

## 6. Popup

改动最小化（popup 已相对干净）：状态徽章颜色与任务页统一；候选卡片的两个下载按钮沿用主/次样式；其余不动。

## 7. 视觉规范

- **令牌化**：现有 CSS 变量扩为完整一套：`--bg/--card/--soft/--line/--text/--muted/--blue/--ok/--warn/--bad`，间距 4/8/12/16/24，圆角 8/10（现状已接近，成文固定）；
- **暗色模式**：`@media (prefers-color-scheme: dark)` 覆盖一套令牌值即可全站生效——令牌化的直接红利；
- 字体不动（系统栈）；主操作按钮加 2px 投影 + hover 提升，描边按钮 hover 换底色；
- 状态胶囊颜色语义固定：蓝=进行，灰=等待，绿=完成，红=需处理。

## 8. 动效规范（克制清单）

只做这五处，全部尊重 `prefers-reduced-motion`（呼吸高亮已有先例）：

| 位置 | 动效 | 参数 |
|---|---|---|
| 面板展开/收起 | max-height + opacity 过渡 | 200ms ease-out |
| 主操作按钮 hover | translateY(-1px) + 投影加深 | 120ms |
| 进度/覆盖条数值变化 | width 过渡 | 300ms linear |
| 正在捕获的缺口行 | 呼吸底色（已有，保留） | 1.4s |
| 进行型提示条 | 12px 旋转小圈 | 1s linear infinite |

明确不做：页面级转场、骨架屏、粒子/渐变动画、弹簧物理曲线。

## 9. 实施切片（每片独立提交、独立可验收）

1. **`actions-matrix`**：实现 `actionsFor()`，HTML 操作区改为 primary/secondary/overflow 三个容器；36 条 hidden 判断删除。**纯逻辑重排，不改样式**。冒烟测试改为按矩阵断言每个状态的可见按钮集合（这是本切片的验收标准，也是回归护栏）。
2. **`layout-hero`**：操作区上移、数字卡压行、两条进度条合并。
3. **`accordion`**：四面板手风琴 + 状态驱动的默认展开。
4. **`notice-tones`**：提示条四型 + 完成弹窗改为可配置。
5. **`tokens-dark`**：令牌整理 + 暗色模式。
6. **`motion`**：§8 的五处动效。
7. **`list-page`**：下载中心卡片改造。

风险控制：
- 所有现有 id **保留不改名**（契约测试和用户肌肉记忆都依赖它们），overflow 菜单只是移动 DOM 位置；
- 每片跑全量 pytest + 冒烟；切片 1 完成前不动任何视觉；
- i18n：新增 key 走既有双语流程，不删旧 key（避免破坏历史任务的持久化消息）。

## 10. 验收标准

- 任何状态下，操作区可见按钮 ≤ 4（1 主 + 2 次 + 更多）；
- 首屏（不滚动）能看到：标题、状态、主操作、覆盖条、提示条；
- 每个 error 状态的提示条与主操作构成「问题→解法」配对；
- 暗色模式下所有文字对比度 ≥ 4.5:1；
- `prefers-reduced-motion` 下无任何持续动画；
- 冒烟测试覆盖矩阵中每一行的按钮集合断言。


## 10. 切片 1 实施记录（2026-08-05）

动手时的现状比 §1 记录的更差：45 个带 id 元素、**20 个按钮**、**44 条 `.hidden`**（新增的全是字幕相关按钮）。

已落地：

- **`availableActions()` / `actionsFor()` / `renderActions()`**：每个按钮只声明一次（可用条件 + 文案 + 禁用原因），排序规则集中在 `PRIMARY_ORDER` / `SECONDARY_ORDER`。render() 不再逐个算 hidden —— 现在只剩 10 条，且全部是面板/画布，没有一条是按钮。
- **HTML 里 0 个写死的操作按钮**（原来 20 个），操作区变成一个 `#actionBar` 容器。
- **一个委托监听**取代 20 个 `addEventListener`；`ACTION_HANDLERS` 是唯一的分发表。
- **四个常驻面板改成 `<details>` 手风琴**，缺口面板默认展开，其余默认收起。播放加速控件移进缺口面板（它只影响补缺口）。
- **字幕的 4 个补救按钮收进「更多」**，表面只留「保存字幕」。
- **诊断面板不再默认展开** —— 结果和原因现在都会到状态行，日志回归"出问题才看"。
- **视觉层重写**：设计令牌（间距/圆角/阴影/缓动各一套）、粘性顶栏、状态胶囊带呼吸点、按钮 hover/active/focus-visible 反馈、溢出菜单弹出动画。动效克制，且 `prefers-reduced-motion` 下**全局**关闭（不只是呼吸高亮）。

测试期间矩阵抓到两个真 bug：`exporting`（正在导出成品）时「打开生成的视频」和「检查并生成视频」都会成为主操作，但那时文件还没导完。两处条件都漏了 `exporting`，已修。

冒烟测试新增矩阵契约断言，跑 **3 种任务形态 × 3 种模式 × 10 种状态**：主操作 ≤1、次操作 ≤2、无重复、每个出现的操作都必须有 handler、merging/exporting 时不得有主操作、主操作确实出现在 DOM 里。契约测试另外断言"声明的操作集合 == 接线的 handler 集合"，防止以后加了按钮忘记接线（或反之）。
